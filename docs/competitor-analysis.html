FitCoach · 产品调研

AI 教练 / 教案生成赛道竞品分析

为验证 FitCoach 的产品定位，对国内外「AI 训练计划生成」与「教练端 SaaS」两类产品做定性对比， 明确差异化切入点与优先级。

调研方法说明： 基于各产品公开官网、应用商店形态与公开报道做定性对比； 动作库规模等具体数字以各产品官方为准，本页不做精确断言。 尚未开展用户访谈，访谈结论将作为后续迭代输入。

一、对标产品与维度对比

二、市场空白与 FitCoach 差异化

① 中间空白

C 端 AI（Fitbod / Freeletics）解决「自己练」，B 端 SaaS（Trainerize）解决「教练做计划管理」， 但「教练按学员年龄 / 水平快速生成、且带安全约束的教案」这一具体场景仍是空白—— 尤其垂类（健身 + 篮球）教练备课，现有工具要么太泛、要么缺安全合规层。

② FitCoach 的切入角度

  • 垂类深耕：聚焦健身 + 篮球教练备课，而非正面竞争 C 端大用户量产品。
  • 安全合规作卖点：年龄分层硬约束（幼儿禁负重等）是 C 端普遍弱化的点，FitCoach 把它做成生成后校验层。
  • 开源可审计：基于 1300+ 开源标准动作库，动作来源可查、可改、可自托管。

③ 作为 PM 的判断（优先级）

  • C 端产品用户基数大、竞争激烈，FitCoach 不应正面竞争，应先深耕垂类教练场景验证 PMF。
  • 「安全校验」是最易感知的差异化，应作为核心传播点，而非堆功能。
  • 下一步高价值动作：做 3–5 位教练的用户访谈，验证「年龄分层约束」是否真为付费动机。

三、结论

FitCoach 卡在「C 端 AI 自练」与「B 端教练管理」之间的垂类备课空白，以 年龄分层安全约束 + 开源可审计动作库作为差异化锚点。 这是一个典型的「发现痛点 → 用 AI / 工具解决」产品思路，也是本项目作为 AI 产品经理作品的核心叙事。
